# Week 6 · Observation

## Task 1 · Link state by hand

- 동점이면 첫 홉 중 이름이 가장 작은 것 하나를 고른다. 결정적이라 매번 같은 답이 나오지만 한 링크로 몰리고, 실제 라우터는 동점 경로 모두에 나눠 보낸다(ECMP). 교재의 동점 규칙이 실제 라우터에서는 ECMP로 나타나는 걸 Task 2 표에서 확인했다. r1이 r2–r3 네트워크를 `via r2`, `via r3` 두 줄로 동시에 설치했다.
- `u`의 `w`행 다음 홉은 `w`가 아니라 `x`다. 직접 링크 u-w는 5지만 u-x-y-w가 1+1+1=3이라, w 인터페이스로 내보내면 이웃 관계를 계산한 것이지 라우팅이 아니다.
- `u-x`가 끊기자 x, y, w, z의 다음 홉이 모두 x에서 v로 바뀌었고 v만 그대로였다. 이때 w는 직접(5)과 v 경유(2+3=5)가 동점이 되어 규칙대로 v를 골랐다.

## Task 2 · Break a real network

- 국내(`www.korea.ac.kr`)는 2번 홉 `121.168.41.129`에서 카페 망을 벗어나 KT로 들어갔고 11번 이후는 차단(`* * *`)이었다. 해외는 3주차에서 `www.stanford.edu`가 Netlify CDN이었던 것과 같은 이유로 국내 9홉에서 끝나 해외 구간이 보이지 않아, `gaia.cs.umass.edu`를 더 쟀다(`-w 2 -m 30`). 7번 16 ms → 8번 137 ms로 한 홉에 +120 ms가 늘고 9번이 `…pao1…gtt.net`(Palo Alto)이라 KT의 태평양 횡단 케이블로 미국 서해안에 상륙한 것으로 보인다. `1.1.1.1`은 10홉 17 ms라 국내 복제본이다. `* * *`는 중간 라우터가 응답만 안 할 때(뒤 홉은 다시 응답)와 그 뒤가 방화벽으로 막혔을 때(끝까지 무응답) 두 경우였다.
- 각 라우터는 직접 연결되지 않은 네트워크도 OSPF로 배웠다. r1–r3를 끊자 r1은 0.9초, r2·r3는 9.9 · 9.1초 걸렸다(hello 10초, dead 40초, 설정 파일엔 없고 기본값). 처음엔 `task2.md`대로 40초 근처를 예상했지만, 측정이 맞지 않아 같은 조건으로 다시 끊어 LSA 순번을 추적했다. 재현에서도 r2·r3가 약 9.5초였고, r1은 자기 링크가 꺼진 걸 즉시 알고 0.5초 안에 LSA를 세 번 고쳐 냈는데, r2가 1초 안에 온 같은 LSA를 버려(min arrival 1초) 재전송(5초)으로 최종본을 받느라 10초가 걸렸다. r2를 말없이 멈춘 경우에만 36.6초로 dead interval이 그대로 보였다.
- 복구는 r3 기준 19.7초로 끊기보다 길었다. 꺼진 링크는 그 자리에서 알지만, 켜진 링크는 hello로 이웃을 다시 찾고(최대 10초) DB를 교환해 Full이 된 뒤에야 경로에 쓴다. 비용 변경(r1–r2, 10 → 100)은 링크가 살아 있어 알아챌 필요 없이 LSA만 퍼지면 되므로 r1 · r3가 약 1초에 바뀌었고, OSPF 비용은 나가는 인터페이스마다 따로라 r2의 표는 그대로였다.

## Task 3 · Incremental reconvergence

- 이벤트 사이에 각 노드의 거리와 처음 도착한 부모(최단 경로 트리)를 유지한다(400 + 399개, 약 36 KiB). 전체 SPF를 할 때는 `dijkstra_table()`로 세고, 바로 뒤에 같은 순서로 트리를 한 번 더 기록한다.
- 트리 밖 링크가 끊기거나 비싸지면 건너뛰고, 트리 밖 링크가 생기거나 싸지면 `dist[a] + 비용 <= dist[b]`(더 짧거나 동점)일 때만, 트리 링크의 비용이 바뀌면 서브트리를 같은 만큼 옮겨 경계에 새 동점 · 지름길이 생길 때만 다시 계산한다. 트리 링크가 끊기는 경우는 항상 전체 SPF다. 결과는 335번(67%, good)이고 1,000번 모두 표가 맞았다. 1,000번 중 약 240번은 표가 실제로 바뀌어, 건너뛰기만으로는 최선이 약 76%다.
- 실행 시간은 0.94초로 baseline(0.57초)보다 느렸다. Python에서는 트리 기록과 서브트리 검사의 dict 연산이 아낀 SPF보다 비싸기 때문이다. Python이 부족한 건 명령 한 줄의 속도이고, 라우터가 부족한 건 SPF를 돌릴 CPU 시간이다. 그래서 같은 코드가 두 곳에서 다르게 평가된다. 라우터에서는 링크 하나가 깜빡일 때마다 영역 전체 라우터가 돌리는 SPF가 비싸고, 내 판단은 링크 하나와 서브트리만 보며 메모리 수십 KB면 된다.
